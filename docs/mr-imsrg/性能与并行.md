# 性能与并行

## 1. 并行方式

单进程 OpenMP（imsrg++ 没有 MPI）。MR 新增部分都按 imsrg++ 原有对易子的模式并行，`schedule(dynamic, 1)`：

| 部分 | 并行单位 | 怎样保证与线程数无关 |
|---|---|---|
| SR 对易子、Pandya、BCH | imsrg++ 原有 | 原有 |
| MR 标量 IV、VI | 第一个轨道指标 | 每个输出元素由一个线程按原顺序累加 |
| MR 标量 V | (J, 宇称, ΔTz) 块 | 各块偏迹写自己的缓冲，按固定块顺序相加 |
| MR 张量 λ2 项 | 偏迹任务（每任务逐块生成中间量） | 每任务独立缓冲，固定顺序归约 |
| White-NCSM 生成元 | 两体通道（单极缓存按轨道） | 每个通道只写自己的 η 块 |
| 对易子 λ3 零体项 | λ3 通道 | 每通道独立求和，按通道顺序相加 |
| 3N 的 MR-NO2B（流前一次） | 二体通道（Γ3）、同通道轨道对（f3） | 每个元素一个线程；λ3·V3 项串行 |

**逐位可复现**：设 `OPENBLAS_NUM_THREADS=1` 时，结果与 `OMP_NUM_THREADS` 逐位无关。不设时 OpenBLAS 自身的多线程带来 1e-15 级差异
（物理上无影响，但比较两次运行时要知道）。`gen_job.py --mr-jscheme` 目前把它设为 CPU 数。

扩展性（He4 嵌入 emax8，point7 node3，每 RK4 步）：1 线程 5.06 s，4 线程 1.82 s，16 线程 1.15 s，64 线程 1.16 s。
emax8 的通道太小，16 线程以上没有收益；更大 emax 的扩展尚未测（TODO）。16 线程稳态每步：SR 对易子约 0.65 s，MR 增量约 0.15 s，
生成元约 0.04 s，其余约 0.3 s 为算符加减、复制与范数。emax12 一步流实测中 MR λ2 增量只占 4.7%，MR 部分不是瓶颈。

集群计时只在同一分区、同一节点类型内比较；邻居负载会带来约 8% 的差异。

λ3 零体项与算符无关的部分（分组、6j、加权 λ3 子块）每个参考态只建一次；He4 嵌入 emax6 约占一次 MR 对易子的 8%。

## 2. 张量对易子提速（算符演化用）

He4 Nrefmax=2 嵌入 emax6/8，随机 [Ω, E2]，本机 4 线程、`OPENBLAS_NUM_THREADS=1`，第二次调用（缓存已建好）：

| | 优化前 | 优化后 |
|---|---|---|
| emax6 耗时 / 峰值内存 | 2.27 s / 420 MB | 0.42 s / 438 MB |
| emax8 耗时 / 峰值内存 | 16.4 s / 1885 MB | 3.5 s / 1849 MB |

做法（imsrg++ 已有的手段推广到张量与 MR 部分，加上几处 imsrg++ 没有的）：

- MR 张量 λ2 项（emax8 约 5.5 s → 0.25 s）：
  - `PairTable`/`BlockAccess`：矩阵元按通道与块指针一次解析后直接读，代替 `GetTBME_J` 的 map 查找；
  - `AngularTables`：6j/9j 按 j 值组合制表，静态保留、跨调用复用；
  - 含 λ 的乘积只在活跃 ket 上做；PT(OλΩ)、R(O, Ω) 由厄米共轭得到，不重复计算；
  - 交叉耦合矩阵按 (J, 宇称, Tz 差) 分块；P、W2 等中间量在偏迹任务内逐块生成、用完即丢（原先整份存，约为张量两体部分的 4 倍）。
- SR 张量对易子（上游路径，SR 计算同样受益）：
  - 张量 Pandya 正、逆变换的重耦合系数按 (L, J_bra, J_ket, j 四元组) 缓存（`RecouplingCache`）；
  - 逆 Pandya 改为每个 bra 对一个任务，轨道四元组的交叉耦合值只读一次再套用到所有 (J1, J2) 块，交叉耦合块用稠密指针表；
  - `comm222_pp_hh_221st` 的一体部分按轨道遍历已存块。
- 结果与优化前相对差 ~1e-15（缓存的 9j、求和次序），`MRTensor` oracle 与全部测试通过。
- 余下耗时（emax8 每次约 3.5 s）：上游逆张量 Pandya 约 1.5 s（离散读取为主）、三组 BLAS 矩阵乘约 1.6 s、MR 部分约 0.25 s。

## 3. 缓存与环境变量

单位 MiB；0 关闭缓存（scratch 类则限制为单个工作线程）；非法值用默认值。

| 变量 | 默认 | 作用 |
|---|---|---|
| `IMSRG_TENSOR_RECOUPLING_CACHE_MB` | 2048 | 张量 Pandya 重耦合系数缓存，超出预算的部分现算 |
| `IMSRG_SCALAR_PANDYA_CACHE_MB` | 1024 | 标量 Pandya 计划（上游） |
| `IMSRG_TENSOR_SCRATCH_MB` | 8192 | 张量两体通道乘积的稠密临时区总预算，决定并发通道数（至少 1 个） |
| `OPENBLAS_NUM_THREADS` | — | 设 1 获得逐位可复现 |
| `OMP_NUM_THREADS` | — | OpenMP 线程数 |

## 4. 内存

MR-IMSRG(2) 的内存由 J-scheme 两体矩阵元决定：H、H(s)、Ω、η、Dormand–Prince 各级导数、BCH 中间量，各为一个两体算符；张量算符约为标量的 2–3 倍。
不做 IMSRG(3)，Ω 分段写 scratch，所以没有三体或 Ω 序列的内存。

| 体系 | 峰值 RSS | 备注 |
|---|---|---|
| He4 嵌入 emax8，单线程 | 约 1.9 GB | 含上游 Pandya 计划与重耦合缓存 |
| He4 嵌入 emax12，64 线程，flow_RK4 一步 | 25.6 GB | 裸 J64 2.1 GB，嵌入 jref 1.2 GB |

本轮新增的常驻内存是角动量与重耦合缓存（emax8 约 0.2 GB）；环形项的交叉耦合矩阵是临时量（emax8 约 0.1 GB，emax12 估计约 0.6 GB）。
MR 标量 λ2 项只在活跃支撑上存中间量，emax12 下避免了约 2.3 GB 的稠密临时量。

## 5. 计时

profiler 计时项（运行结束时随 profiler 表打印）：`MR lambda2 commutator addons`（MR 增量总时间）、`MR comm221 lambda2 IV`/`V`/`VI`/`setup`
及 V 的 build、BLAS、partial trace 子项、`MR comm221 lambda2 tensor total`/`tensor ring`/`tensor products and traces`、`WhiteNCSM monopole cache`，
以及 imsrg++ 原有的对易子与生成元计时。V 的子项是各线程时间之和。
