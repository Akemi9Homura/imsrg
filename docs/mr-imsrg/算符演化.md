# 算符演化（Magnus Ω）

## 1. 为什么用 Ω 变换

IM-NCSM 的观测量（半径、E2、M1 等）要和 H 用同一个幺正变换：O(s) = U(s) O U†(s)。Magnus 方法把 U 存成 e^Ω，流跑完后对任意算符做
O(s) = e^Ω O e^{−Ω}（BCH 级数），不需要在流开始前决定算哪些算符，也不必把每个算符和 H 一起积分（成本随算符数线性增加，且误差各自累积）。
IM-NCSM 文献的做法相同：Vobig 2020 实现 Magnus(2) 并推导任意张量秩的 MR 对易子，此后观测量都用 Magnus；Mongelli 2022 沿用。

实现沿用 imsrg++ 的算符流程，任意算符走同一条路径，MR 只替换换基与正规序：

| 步骤 | SR（imsrg++ 原有） | MR |
|---|---|---|
| 构造 | `OperatorFromString` 或从文件读 | 同 |
| 换基与正规序 | HF/NAT 换基，`DoNormalOrdering` | 自然轨道换基，`MRReference::NormalOrder`（与 H 相同） |
| 演化 | `IMSRGSolver::Transform`，逐段套用 Ω（含写入 scratch 的段） | 同；BCH 内部调用 MR 对易子 |
| 导出 | `UndoNormalOrdering` | `MRReference::UndoNormalOrder`，转回 HO，与 H 同格式 |

标量与张量只在三处分开：对易子的 λ2 项（标量 IV/V/VI + 零体；张量只有一体，见 MR对易子与正规序.md）、MR 正规序（张量不加 λ2 零体项）、写出格式。

## 2. 用法

在 MR 运行里加 `Operators=`（逗号分隔的内建算符名）或 `OperatorsFromFile=`，method 必须是 Magnus 族：

```bash
imsrg++ ... method=magnus_adaptive mr_reference_file=He4.jref \
  scratch=omega_scratch Operators=Rp2,Rm2,E2,M1 \
  write_H_jcoupled64=H.jcoupled64 write_H_no2bpack=H.no2bpack
```

- `scratch` 必须是可写目录：Ω 分段写在这里，变换时依次读回。`scratch=/dev/null` 加算符会被拒绝；`scratch` 为空时 Ω 留在内存。
- 不给 `write_H_*` 时只在日志里打印参考态期望值，不导出。
- 支持：偶宇称、不改变同位旋的标量（Rp2、Rm2、Rn2、rso 等）；秩 L > 0、不改变同位旋的张量（E2、M1、E1 等）。
- 拒绝（流开始前）：改变同位旋的算符（GT、Fermi）、奇宇称标量、三体算符、PT1/RPA/TDA、`write_HO_ops`、`write_HF_ops`、非 Magnus 方法。

## 3. 输出

| 算符 | 文件 |
|---|---|
| 标量 `Rp2` | `H_Rp2.jcoupled64`、`H_Rp2.no2bpack`（H 的路径在扩展名前加 `_Rp2`）+ 各自的 `.mrmeta.json`（`operator` 字段为算符名） |
| 张量 `E2` | `H_E2.opbin`（`Operator::WriteBinary`：秩、宇称、1B 与 2B 约化矩阵元，无损）+ `.mrmeta.json` |

都是真空正规序、原 HO 基，与导出的 H 配套。张量写成 `.opbin` 是因为 jcoupled64/no2bpack 只能装标量。

日志（标量）：

```
   <Phi|O|Phi>: ...          流前参考态期望值
   <Phi|O(s)|Phi>: ... (reference expectation value, not the IM-NCSM one)
IM-FCIQMC export check: Rp2(s).ZeroBody = ...  difference = ...
```

⟨Φ|O(s)|Φ⟩ 只是参考态在变换后算符下的期望值；IM-NCSM 的观测量要用导出 H 在 Nmax 空间的本征态去算导出的 O(s)。

## 4. 截断与近似

- O(s) 截断在两体（MR-IMSRG(2)）；参考态带 λ3 时，标量算符 BCH 中的对易子零体含 λ3 项（只影响期望值常数），张量不受影响；
  没有 Mongelli 2022 在观测量 BCH 里加的领头阶诱导三体修正；
- 张量与标量用同一组 Ω，BCH 收敛判据相同（MR 下不收敛直接报错）。

## 5. SR 侧的修正

上游只在 `method=magnus` 时做流后变换；`magnus_euler`、`magnus_adaptive` 下算符既不随流演化也不变换，单参考输出分支还会越界读 `FlowingOps`。
现在 Magnus 族统一走流后变换，SR 一并修正，并同样能导出真空形式（用于 SR 退化对照）。

| `MRTensor` | 相关 He4 Nrefmax=2 参考，[Ω, O]（E1、M1、E2）对稠密 m-scheme oracle；张量 MR 正规序往返 | ≤ 2e-14；≤ 1.3e-15 |
