# 驱动参数与输出

MR 模式不是单独的程序：给 `imsrg++` 传 `mr_reference_file=<jref>` 就进入 MR 路径。这样换基、读写、求解器、算符变换全部沿用 imsrg++ 的代码，
MR 只替换三处：自然轨道换基与 MR 正规序（流前）、对易子的 λ2 项（流中）、撤销 MR 正规序与转回 HO（导出）。

## 1. 参数

### 1.1 必须这样设的

| 参数 | 值 | 原因 |
|---|---|---|
| `mr_reference_file` | jref 路径 | 打开 MR 模式 |
| `basis` | `oscillator` | 参考态自带 HO→自然轨道变换，不做 HF |
| `core_generator` | `white-ncsm` | 唯一实现了占据加权分子与 MR-EN 分母的生成元 |
| `denominator_partitioning` | `Epstein_Nesbet` | White-NCSM 只定义了 EN 分母 |
| `3bme`、`3bme_type` | `none`，或 3N 文件加 `full`/`no2b` | 3N 做 MR-NO2B（见 三体力与λ3.md）；`mono` 拒绝。给 3N 时同时设 `e3max` 与 `file3e1max/file3e2max/file3e3max` |
| `BetaCM` | `0` | 参考态 NCSM 与输入相互作用都不含 Lawson 项，流里加上会让 H 与参考态不一致 |
| `nsteps` | `1` | 只有一段流（不做价空间第二段） |
| `reference`、`A` | 与 jref 的 A、Z 一致 | 驱动核对，不符即退出 |
| `valence_space` | 与 `reference` 相同（如 `He4`） | 不能有价空间 |
| `nucleon_mass_correction` | `false`（`fmt2=jcoupled64` 时） | jcoupled64 已含完整的 A 依赖真空 H |

`denominator_delta=0` 是生产设置。下列选项在 MR 下会被拒绝：IMSRG(3)、`imsrg3_at_end`、`perturbative_triples`、goose-tank、Brueckner BCH、
`emax_imsrg`/`e2max_imsrg`/`e3max_imsrg` 二次截断、PT1/RPA/TDA 算符、`write_HO_ops`、`write_HF_ops`。拒绝发生在启动时，不会算完才报错。

### 1.2 求解方法 `method`

| 值 | 做法 | 用途 |
|---|---|---|
| `magnus_adaptive` | 完整 Bernoulli Magnus ODE dΩ/ds = Σ_k B_k/k! ad_Ω^k(η)，Dormand–Prince 5(4) 自适应步长 | **生产** |
| `magnus`、`magnus_euler` | 指数 Euler：每步 Ω ← BCH(η ds, Ω) | 代数对照（oracle），步长误差一阶 |
| `flow`、`flow_adaptive` | 直接积分 dH/ds = [η, H]（odeint 自适应） | 有限 s 窗口、短流对照 |
| `flow_euler`、`flow_RK4` | 定步长直接流 | 测试 |

为什么生产用 `magnus_adaptive`：

- 慢尾要求很长的 s（He4 emax2 走到 s ≈ 4×10^5），定步长 Euler 的步长误差会累积；Magnus 只积分 Ω，H(s) 每步由 e^Ω H e^{-Ω} 重建，误差不在 H 上累积；
- 算符演化必须有 Ω（见 算符演化.md），直接流只能把算符跟着 H 一起积分，MR 下不支持；
- 做法与 Vobig 2020（4.6.4 式，GSL RKF45）一致；这里用 imsrg++ 已有的 Boost odeint Dormand–Prince，同属嵌入式 5(4) 方法。

`magnus_adaptive` 的级数截断（Vobig 4.6.7–4.6.8）：每次求导在 k ≥ 2 的非零 Bernoulli 项相对小于累积导数时停止；若嵌套对易子范数不下降，
或到 k = 8 仍未收敛，就拒绝该试探步、步长减半；同一段连续拒绝 8 次，或在已接受的状态本身就不收敛时，把已接受的 Ω 固化为一段、从 Ω = 0 重新开始。拒步与重启写在日志里。

### 1.3 与流长、精度有关的参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `smax` | 200 | 流的终点 s。慢尾体系要设得很大，靠 `eta_criterion` 停 |
| `eta_criterion` | 1e-6 | ‖η‖（绝对值，MeV）低于它就停，与 imsrg++ 所有求解器相同。验收时用过更严的相对门槛 ‖η‖/‖η(0)‖ < 1e-6（He4 emax2：‖η(0)‖ = 0.7036，取 7e-7）；‖η(0)‖ 为 O(1) MeV，两者相差不到 2 倍，日常用默认值即可 |
| `ode_tolerance` | 1e-6 | Dormand–Prince 的绝对、相对容差；`gen_job.py --mr-tight-validation` 用 1e-7 做复核 |
| `ds_0`、`dsmax` | 0.5、0.5 | 初始、最大步长 |
| `omega_norm_max` | 0.25 | ‖Ω‖ 超过它时开新的一段 Ω，旧段固化（BCH 级数在 ‖Ω‖ 小时收敛快） |
| `mr_validation_tolerance` | 1e-10 | jref 校验与基变换正交性的容差 |

### 1.4 Ω 的存放与算符

| 参数 | 说明 |
|---|---|
| `scratch=<目录>` | 每段 Ω 固化时写到 `<目录>/OMEGA_<pid><序号>` 并从内存释放。长流会有很多段，生产必须设。驱动把段数上限设为 500（`max_omega_written`），超过即终止；`scratch=/dev/null` 表示丢弃 Ω（只要 H 时可用，有算符时拒绝） |
| `write_omega=true` | 结束时把各段 Ω 复制为 `<intfile>_Omega_<i>`，可用 `imsrg_operator_validate --emax E --hw HW --reference NAME OMEGA...` 检查 |
| `Operators=Rp2,E2,...` | 要演化的内建算符（只限 Magnus 方法），见 算符演化.md |
| `OperatorsFromFile=...` | 从文件读入的算符，同上 |

## 2. 输出

### 2.1 导出文件

给 `write_H_jcoupled64=X.jcoupled64` 和/或 `write_H_no2bpack=X.no2bpack` 时，导出 H(s) 的**真空正规序、原 HO 基**形式（先撤销 MR 正规序，
再用自然轨道变换的转置转回 HO）。下游拿到的是普通的零、一、两体真空 Hamiltonian，与 NCSM 的输入格式相同，不需要知道参考态。

`mr_export_basis=natural`（默认 `oscillator`）跳过转回 HO，导出在 MR 基（jref 的 C_total 列，例如 HF 基参考态时的 HF·NAT 基）里的真空 H 与算符，
`.mrmeta.json` 的输出基随之注明。用途：参考态在 HF/NAT 基里算时，后对角化也在同一基的 Nmax 空间做（Nmax=0 即参考空间，s 处的 Nmax=0 能量等于 E(s)）。

| 文件 | 内容 |
|---|---|
| `X.jcoupled64` | 无损 J 耦合二进制（imsrg++ 读写，`compare_jcoupled64.py` 可比较） |
| `X.no2bpack` | NCSM/FCIQMC 读的压缩格式 |
| `X_<名字>.jcoupled64` / `.no2bpack` | 标量算符（`Rp2` 等），路径为 H 的路径在扩展名前加 `_<名字>` |
| `X_<名字>.opbin` | 张量算符（`E2`、`M1` 等）：标量格式装不下，用 `Operator::WriteBinary`（秩、1B、2B 约化矩阵元），`Operator::ReadBinary` 读回 |
| `<上述文件>.mrmeta.json` | 每个导出文件旁的说明（见下） |
| `<intfile>_Omega_<i>` | `write_omega=true` 时 |

`.mrmeta.json`（schema `imsrg_mr_export_v1`）：输出格式、算符名、构建版本、截断（MR-IMSRG(2)，λ3 = 0）、生成元及分子不含 λ、分母分区、
解耦掩码（Δe ≠ 0 的 1p1h、2p2h，按自然轨道继承的 e = 2n + l）、输出基、`method`、`s_final`、`smax`、`ds_0`、`dsmax`、`ode_tolerance`、
`eta_criterion`、参考态量子数（A、Z、Nrefmax、2J、宇称、emax、e2max、ħω）、三个 SHA-256。
写成单独文件是因为 jcoupled64/no2bpack 是固定二进制布局，下游程序在读，不能加字段。

带 3N 或 λ3 时（schema `imsrg_mr_export_v2`）另有：`lambda3.in_reference`、`lambda3.commutator_zero_body_term`、
`three_body.input/file/normal_ordering/lambda3_zero_body_term/e3_gamma1_cubed/e3_gamma1_lambda2/e3_lambda3`、
`reference.reference_energy(_label)`。

### 2.2 日志

| 行 | 含义 |
|---|---|
| `Enabled explicit J-scheme MR-IMSRG: reference=... A= Z= Nrefmax= lambda3=0 interaction_sha256=` | 进入 MR 模式 |
| `MR reference lambda3: present/absent; zero-body lambda3 term of the commutators: on/off` | 参考态是否带 λ3 |
| `MR-NO2B 3N (...): E3 = A(g1g1g1) .. + A(g1 lambda2) .. + lambda3 ..` | 给 3N 时：3N 零体的三部分 |
| `MR-NO2B 3N: lambda3 x V3 zero-body term included / omitted (原因)` | λ3·V3 项是否计入 |
| `MR initial natural-basis Hamiltonian: E= ||f||= ||Gamma||=` | 自然基 MR 正规序后的初值；参考态用同一个 H 算时 E 等于 NCSM 参考能量 |
| `MR reference energy from the reference file (...): ...  initial E - E_ref = ...` | jref 带参考能量时的核对（3N 时只有 λ3·V3 计入且参考态用显式 3N 才严格为 0） |
| 流程表 | 列：步、s、`<Phi|H(s)|Phi>`、‖H‖、误差估计、‖Ω1‖、‖Ω2‖、‖Ω3‖、‖η1‖、‖η2‖、‖η3‖、对易子数、**`dE0/ds`**、算符数、墙钟、内存 |
| `Magnus series rejected at s=...` | 级数拒步或段重启 |
| `<Phi|O|Phi>`、`<Phi|O(s)|Phi>` | 标量算符的参考态期望值（流前、流后） |
| `IM-FCIQMC export check: ... difference =` | 导出往返核对：撤销正规序后再正规序的零体项与 H(s) 零体项之差，应为舍入误差 |
| `MR reference energy <Phi|H(s)|Phi> = ... (not the IM-NCSM energy: diagonalize the exported H)` | 结尾 |

SR 的 MP2 列在分数占据下无定义，MR 改为相邻两行的后向差分 dE0/ds（第一行为 NaN）；它趋零说明零体项已稳定。
`<Phi|H(s)|Phi>` 是参考态在 H(s) 下的期望值，**不是** IM-NCSM 能量；IM-NCSM 能量要把导出的 H 在 Nmax 空间里对角化。

注意：`flowfile` 与 stdout 写同样的行；判断进度看 stdout 或流程文件的末行，不要用早期归档里被截断的流程文件估时。

## 3. 下游读回

原型桥 `mrimsrg_validate`（`prototype/mrimsrg/cpp/validate_flow.cpp`，依赖 simple-ncsm，用 `-DSIMPLE_NCSM_ROOT=...` 构建）：

```bash
mrimsrg_validate --no2bpack H.no2bpack --Z 2 --N 2 --nmax 10 --states 3 [--max-iter 500]
mrimsrg_validate --interaction X.minipack --jcoupled64 H.jcoupled64 --Z 2 --N 2 --nmax 4
```

no2bpack 自带基组；jcoupled64 需要 `--interaction` 指定活跃基。算符期望值与跃迁的读回尚未实现（TODO）。

BIGSTICK 的 `no2` 读入直接读导出的 no2bpack（任意单粒子基，零体自动计入，质心项 β 只能取 0；文件名要带扩展名且不能以 "no2" 开头）。
`prototype/mrimsrg/postdiag_bigstick.py --no2bpack H.no2bpack --Z 8 --N 8 --emax 8 --hw 20 --nmax 0 2 4 --workdir D --output r.json`
逐个 Nmax 跑 Lanczos（维数 1 时改用完全对角化 `ex`），写谱与三点指数外推。BIGSTICK 矩阵元单精度，能量差 ~1e-4 MeV。
FCIQMC 直接读 `H.no2bpack`（im-fciqmc 的 IM-FCIQMC 流程）。

## 4. 相互作用输入

驱动吃 imsrg++ 能读的两体格式；目前验证过的是 `fmt2=jcoupled64`，由 NCSM 用的 minipack 转换：

```bash
mrimsrg_minipack_to_j64 --interaction X.minipack --output X.jcoupled64 --A 4
```

转换结果含完整的 A 依赖真空 H（含内禀动能），所以 `nucleon_mass_correction=false`。参考态与流必须用同一个相互作用，驱动不核对，
检查方法是初始 E 等于 NCSM 参考能量（jref 带参考能量时驱动直接打印差值）。

3N 另给 `3bme=<文件> 3bme_type=full|no2b`，与 NN 文件的 ħω 一致，`e3max`、`file3e*max` 按文件设；用法与限制见 三体力与λ3.md。

## 5. 集群作业：`gen_job.py`

三个 MR 模式，各自生成带 SHA-256 自检、RSS 采样和 `metadata.json` 的 Slurm 脚本，结果目录已存在时拒绝覆盖：

| 模式 | 做什么 | 主要选项 |
|---|---|---|
| `--mr-jscheme` | 一次生产 MR-Magnus 流（上面 1.1 的固定参数 + `magnus_adaptive`、`scratch`、`write_omega`、两种导出） | `--mr-nucleus --mr-nrefmax --mr-emax --mr-interaction --mr-reference-file --mr-target-s [--mr-start-s] [--mr-eta-criterion 1e-6] [--mr-tight-validation]` |
| `--mr-prepare-jscheme` | 目标 emax 的 J64 相互作用（`mrimsrg_minipack_to_j64`）与嵌入的参考态（`embed_jref.py`） | `--mr-nucleus --mr-nrefmax --mr-emax --mr-minipack --mr-source-reference --mr-converter --mr-pyimsrg-dir` |
| `--mr-ncsm-readback` | 下游 NCSM 读回（`mrimsrg_validate --no2bpack`） | `--mr-ncsm-no2bpack --mr-z --mr-n --mr-nmax [--mr-states 3] [--mr-max-iter 300] --mr-ncsm-executable` |

公共选项：`--mr-partition`（c128m1024/c128m512/compute_C/compute_A，默认 c128m512）、`--mr-cpus`（默认 64）、`--mr-nodelist`、`--mr-label`、
`--mr-result-root`、`--generate-only`/`--submit`。核与 Nrefmax 目前限于已有参考态（He4 0/2、Be8 0、C12 0、O16 0/2），ħω = 20。

生成的流作业把 `OPENBLAS_NUM_THREADS` 设为 CPU 数；要求结果与线程数逐位无关时改成 1（见 性能与并行.md）。
